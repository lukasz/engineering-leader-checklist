# Documentation 📃

[The Engineering Leader’s Checklist](../README.md)

Up-to-date, meaningful documentation is something every single organisation I worked for struggled. Here are some tips on how to make it less of a pain and more useful. 

## Checklist
- **Make it „live”** - e.g. stack overflow style - updated in real-time, focused on real problems 
- **Close to the code** - e.g. README files, making updating them part of the Definition of Done
- **Automate** - you can use certain standards that will help you generate some docs automatically (e.g. OpenAPI)
- **Make part of the process** - make sure that writing documentation is part of the overall process of developing a feature, which could include things like:
  - design documents like PRD or ADRs
  - autogenerated docs from code using, for example, the OpenAPI standard
  - making architecture diagrams, README files, changelog updates, etc., a part of the development process / Definition of Done
  - writing down post-mortems after any incident
- **Architecture**
  - C4s - keep up to date 
  - ADRs & Spikes - document your discovery and decision-making 
- **Pre & Post Mortems** - document a discovery/analysis of what could go wrong with a feature or what did go wrong after an incident
