# Roadmaps 🗺️

[The Engineering Leader’s Checklist](../README.md)

The main purpose of Roadmaps is to have an overview of the work you need to engage in over an upcoming period. There can be various methods and frameworks to do that with a different level of detail, but the bottom line is to gather in one place what you need to do, and how to prioritise it so that you get the right focus and no important thing goes under the radar. 
The checklist items indicate areas of backlog you should consider, and ensure nothing goes unchecked. 

### Checklist 
- **Tech Debt** - updating dependencies (e.g. the newest version of a library), code cleanup, optimising implementations for performance, unifications and migrations in compliance with Tech Radar reviews etc. 
- **BAU / Maintenance** - bugs, non-automated service requests etc. 
- **Product Engineering** - all the product iterations - new features that add value to the product
- **Discovery** - dedicated time to make a proper discovery before any work goes into the implementation phase - much like technical tasks result in codebase shipped, discover should have a tangible output as well - in the form of technical specification for the work in question (like stories, tasks etc.) and potentially additional documentation (like ADR for example) 
- **[SDLC](delivery/sdlc.md)** - Software Development Life Cycle
